# 技術說明書(IT 版)

## 架構
GitHub Pages(靜態前端)→ HTTPS POST → Google Apps Script Web App(執行身分:擁有者、存取:任何人)→ Google Sheets。詳見 ARCHITECTURE.md。

## 首次部署
1. 建立試算表 → 擴充功能 → Apps Script。
2. 依 `gas/` 建立 7 個同名檔案(00_gateway … 60_files),貼上內容並儲存。
3. 執行 `setupSheets` 並授權(讀寫試算表、寄信、指令碼屬性、觸發器)。
   **這一步是必要的**:系統平常找不到工作表時會直接報錯,不會自動建立(見下方「資料保護」)。
4. 執行 `authorizeDrive` 取得雲端硬碟權限(展品照片要用)。
5. 部署 → 新增部署作業 → 網頁應用程式;執行身分「我」、存取權「任何人」→ 複製 `/exec` 網址。
6. 把網址寫入 repo 的 `deploy.config.json` → push → GitHub Actions 測試並發佈。
7. repo Settings → Pages → Source 選「GitHub Actions」。
8. (選用)執行 `installDailyTrigger` 開啟每日 08:30 提醒。
9. **(建議)執行 `installBackupTrigger` 開啟每日備份** —— 每天凌晨 2 點複製一份試算表到雲端硬碟「展品管理備份」,保留 30 天。
10. 開啟網站建立第一位管理者,再到「使用者」匯入人員名冊。

## 更新
- 前端:改原始碼 → `node build.js` 本機驗證 → push。
- 後端:改 `gas/*.gs` → 本機測試 → 貼到 Apps Script → 部署 → 管理部署作業 → 編輯 → **新版本**(網址不變)。

## 資料保護(為什麼有些操作會直接報錯)
「整個系統回到預設值」最常見的原因不是資料被刪,而是程式找不到原本的工作表、於是自己建了一張新的還塞進預設值 —— 異常被偽裝成一個看起來正常的空系統。所以這裡刻意做成**寧可壞掉,也不要自己修好**:

| 情況 | 系統的反應 |
|---|---|
| 找不到工作表(被改名 / 刪掉 / 開到別的試算表) | 直接報錯,**不會**自動建立。確認清楚之後才手動執行 `setupSheets` |
| 工作表標題列缺少關鍵欄位 | 直接報錯(判定「這不是本系統的資料表」),避免把錯的資料當成對的寫回去 |
| 某個動作只讀了部分欄位 / 部分列,卻要整張寫回 | 直接報錯。寫回是「整張清空再重寫」,只讀一部分就寫回會把沒讀到的清成空白 |

前兩種通常代表「開錯試算表」。**看到這類訊息時不要重新執行 `setupSheets`** —— 先確認原本的試算表還在不在,重新初始化等於把資料清空。

## 指令碼屬性
| 鍵 | 用途 |
|---|---|
| SECRET | 簽章 / PIN 雜湊金鑰(自動產生,**勿外流、勿修改**,修改會讓所有 PIN 與登入失效) |
| MAIL_OFF | 設為 `1` 停止寄信 |
| SHEET_ID | (選用)改用其他試算表。**設錯或被清掉會讓系統指到別的檔案**,這也是上面那些檢查要擋的情況 |
