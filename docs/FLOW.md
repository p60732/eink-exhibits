## 一、角色

| 角色 | 登入方式 | 能做什麼 |
|---|---|---|
| 同仁 user | 只輸入**工號** | 查目錄、規劃展覽、送借用申請、申請點交/歸還、查自己的借用 |
| 管理者 admin | 工號 + **PIN** | 同仁的全部 + 核准/退回、點交、驗收、展品與單台維護、盤點、使用者管理、操作紀錄 |

- 同一條網址,系統依角色自動顯示不同分頁。
- 管理者 PIN 連錯 5 次鎖 10 分鐘;首次登入強制改 PIN。
- 憑證為無狀態 token:同仁 7 天、管理者 12 小時;登出會 bump `sessionVer` 讓舊 token 立即失效。

## 二、頁面地圖

```
同仁看到      展品目錄 → 借用申請(購物車) → 我的借用
管理者多看到   總覽 → 借用單 → 展品管理 → 盤點 → 使用者 → 紀錄
```

| 分頁 | 誰看得到 | 用途 |
|---|---|---|
| **總覽 dash** | admin | 最上方「今天要做的事」把逾期、待確認、待審核、今日點交、今日到期收成一張清單,每列一鍵跳過去;下方 KPI 磚與各狀態清單 |
| **借用單 loans** | admin | 依狀態篩選,核准 / 退回 / 點交 / 驗收 / 延期 / 列印;待審核可勾選批次核准 |
| **展品目錄 catalog** | 全部 | 依分類分段 + 上方分類籤條;依日期區間查「這段期間可借幾個」。可逐項加入規劃,也可以多選後按「一起填單」 |
| **借用申請 plan** | 全部 | 購物車 → 填活動資訊 → 送出申請(送出前即時檢查衝突) |
> ⚠️ 「借用申請」(全部人,舊名「展覽規劃」)跟「展覽檔期」(管理者)是兩件事:
> 前者是**單次借用**的購物車,任何理由都走它;後者是**整場展覽**的專案層,先卡位再批次開單。
| **我的借用 mine** | 全部 | 進行中 / 歷史;可修改申請、取消、申請點交、申請歸還、申請延期、轉借、列印 |
| **展品管理 items** | admin | 依分類分段的清單;新增/編輯/下架/刪除展品、上傳照片、單台編號維護、批次匯入、分類管理 |
| **盤點 count** | admin | 依分類分段 + 分類籤條(可以只盤一類);上方總計對照(已盤/應在庫/實點/差異/借出中);逐台品項掃 QR 或勾選、數量品項填實點數,即時算差異;借出中的列在旁邊提醒不用盤,套用差異、標記遺失 |
| **使用者 users** | admin | 姓名/工號/部門/信箱/角色、停用、批次匯入 |
| **紀錄 logs** | admin | 誰在什麼時候改了什麼(before → after) |

## 三、主流程:一張借用單的一生

```
        同仁                              管理者
         │
 ① 展品目錄 選日期 → 加入規劃
         │
 ② 借用申請 填活動/場地/用途/聯絡人 → 送出
         │            ↓ 系統即時檢查可借量
         └──────────► pending 待審 ──────► ③ 核准 approve ──► approved 已核准
                          │                   └ 退回 reject ──► rejected 已退回
                          │
 ④ 到現場 → 我的借用「申請點交」(選要拿的單台)
                          │
                    request=pickup 待確認
                          │
           ⑤ 管理者當面在同仁畫面輸入工號+PIN 確認
              (或管理者自己在後台「點交」)
                          ↓
                       out 出借中  ← 單台狀態變 out
                          │
 ⑥ 歸還時 → 我的借用「申請歸還」(填歸還數/單台)
                          │
                    request=return 待確認
                          │
           ⑦ 管理者當面確認 / 後台「驗收」
                          ↓
              全部還完 → returned 已歸還(單台回 in)
              只還一部分 → 仍是 out,剩下的繼續算佔用
```

**狀態值**:`pending` 待審 → `approved` 已核准 → `out` 出借中 → `returned` 已歸還;
另有 `rejected` 已退回、`cancelled` 已取消。
**請求欄 request**:`null` / `pickup` 待點交確認 / `return` 待歸還確認 / `extend` 待確認延期 / `transfer` 待確認轉借。
一張單同時只能掛一個請求。四種請求都可以由管理者在後台處理,或是同仁把畫面交給管理者「當面確認」。

### 中途會發生的事

| 情況 | 誰發起 | 怎麼走 |
|---|---|---|
| **填錯了想改** | 同仁 | 待審核時按「修改申請」,整張載回借用申請改完存檔,單號不變、仍是待審核。已核准後就不能自己改,要找管理者。 |
| **展期延後** | 同仁 / 管理者 | 同仁按「申請延期」選新的歸還日 → 管理者同意才生效。系統會檢查**多出來的那一段**還借不借得到,不夠會擋下來(管理者可強制)。管理者也能直接延期。 |
| **東西轉給別人** | 同仁 | 按「轉借」輸入對方工號 → 管理者同意後,借用人、部門、聯絡方式一起換人,之後逾期算在新的人身上。 |
| **一次核准很多張** | 管理者 | 借用單頁待審核超過兩張時上方會出現批次列,勾選後一次核准。**其中一張數量不足不會影響其他張**,結束後列出沒過的單號與原因。 |
| **不想逐台勾編號** | 雙方 | 點交與簽收視窗都有「自動指派 / 自動選好」,系統挑在庫的前 N 台,要換哪一台再自己點。 |
| **要紙本簽名** | 管理者 | 借用單卡片按「列印」,產生一張含品項清單與雙方簽名欄的單據。 |

### 可借量規則(核心)
```
某展品在 [start, end] 的可借量
  = 總數(qty 或在庫單台數)
  − 期間內所有 approved / out 尚未歸還的數量
逾期未還者視為「永久佔用」,佔用期間延伸到 9999-12-31,直到驗收為止。
```
這條規則只寫在邏輯積木(`Logic.availableInRange`),前端不重寫,測試有突變測試守著。

## 四、分類

展品分在一組可維護的分類底下,預設七類(可自行增減、改名、調順序):

`eReader`・`eNote`・`Logistics & Factory`・`Prism`・`Signage`・`Lifestyle`・`Mobile & Wearables`

- 分類存在「分類」工作表(`id / name / sort / archived`),**不是**跟著展品跑的自由文字 —— 所以還沒放東西的分類也看得到,一眼知道還缺什麼。
- 展品目錄與展品管理都照 `sort` 的順序分段顯示,上方有分類籤條(各自帶數量)可以只看一類。
- 管理者在「展品管理 → 分類管理」新增、改名、調順序、停用。**改名時底下的展品跟著走**;還有展品的分類不能停用,會提示先把展品改到別類。
- 新增展品時分類是下拉選單,選「+ 新增分類…」可以當場開一個新的;批次匯入遇到沒看過的分類名稱會自動建立。

## 五、兩種追蹤模式

| 模式 | 適用 | 借出時 | 盤點時 |
|---|---|---|---|
| **unit 單台** | 需要追到每一台(機台、樣品) | 指定編號 E0001…,單台狀態 in/out/repair/lost | 掃 QR 或勾選,沒點到的可標記遺失 |
| **qty 數量** | 線材、配件等只需算數量 | 只記數量 | 輸入實際盤點數,套用差異 |

同一張借用單可以同時包含兩種模式的品項。

## 五之一、盤點怎麼對比庫存

| | 應在庫 | 實際點到 | 差異 | 借出中 |
|---|---|---|---|---|
| **逐台品項** | 狀態為「在庫」的單台數 | 掃到 / 勾到的台數 | 點到 − 應在庫,卡片上即時顯示 | 逐台列出編號、在誰手上、什麼活動、哪天還(逾期標紅) |
| **數量品項** | 該品項的 inStock | 手動填的實點數 | 實點 − 應在庫,表格即時顯示 | 顯示台數,點下去看是哪幾張借用單借走的 |

- 「應在庫」**已經扣掉借出中的量** —— 借出去的東西不在倉庫是正常的,不是短少。所以盤點只對比「應該還在倉庫裡的」。
- 上方總計對照只計算**已納入本次盤點**的品項,可以分次盤、分類盤,不用一次盤完。
- 未填 / 未勾選的品項不列入本次盤點,不會被誤判為 0。
- 「把差異套用到系統數量」勾起來才會改動資料;「未點到的單台標記為遺失」預設不勾。

## 五之二、展品編輯

- **分類**與**存放位置**都是下拉選單。存放位置預設放 **新竹、林口**,已經用過的其他地點會一起列出來,選「+ 新增地點…」可以當場加(例如「湖口 B 倉 A-01」)。
- **同一個展品可以同時放在好幾個廠區**。數量型展品在編輯視窗用「各地點的數量」一列一個地點(新竹 2、林口 3),按「再加一個地點」可以加;逐台編號的展品則是每一台各自記自己在哪,搬動就改那一台的地點。
  - 清單與目錄上會直接顯示「新竹 2 · 林口 3」。
  - **借用要指定從哪一個地點借**:只放一個地點的會自動帶入,放兩個以上的目錄卡片上會出現地點下拉。可借量是**分地點各算各的** —— 新竹 3 台借光了,林口那 2 台還是借得到。
  - **點交只能指派該地點的單台**,不會把林口的機器配給新竹的單。
  - **歸還可以選「還到」哪一個廠區**,預設還回原本借出的那一點;選別的廠區就等於庫存跟著搬過去。
  - **盤點可以只盤一個廠區**:盤點頁上方選廠區後,只會列出那一區該有的東西,差異也只算那一區(不然新竹的人盤不到林口的東西會全被當成短少)。各地點的「最後盤點」日也是分開記的。
- **照片**可以直接從手機拍或從電腦選檔上傳。前端會先把圖縮到最長邊 1200px、壓成 JPEG(超過上限會自動降畫質),再交給**檔案積木**存進雲端硬碟的「展品照片」資料夾;**試算表只存連結,不存圖片本身**,所以目錄頁不會因為照片變慢。也可以改用貼網址。
- **下架 vs 刪除**:
  - 下架 = 目錄與規劃頁不再出現,紀錄與可借量都還在,隨時可以上架。**暫時不用就用這個。**
  - 刪除 = 永久移除,連同單台編號一起。**只有從來沒被借過的展品才刪得掉** —— 借過的會被擋下來,因為刪了之後舊借用單會變成「(已刪除)」,查不出當初借了什麼。刪除會寫進操作紀錄(品名、分類、數量)。

## 八、效能設計(切頁變快的做法)

讀取成本三刀,由粗到細:

| 刀法 | 做法 | 例子 |
|---|---|---|
| **① 只讀需要的工作表** | 路由表為每個動作標註要哪幾張表 | 「使用者」頁只碰 Users,完全不讀展品與借用單 |
| **② 只讀需要的欄位** | 同一張表再標註欄位;記憶積木把要讀的欄位合併成少數幾段連續範圍後才向 Sheets 取值(超過七成欄位就整列讀,省下拆段的往返) | 算可借量只需要借用單的 `status / start / end / lines`,不必把 21 欄全搬出來 |
| **③ 只讀沒結案的列** | 先單獨讀 `status` 那一欄,找出第一筆未結案的位置,之後只讀這一段到最後 | 借用單是往後累加的,已歸還的舊單集中在前面,用久了這一刀省最多 |

借用單頁另外還有兩刀:

| 刀法 | 做法 |
|---|---|
| **④ 進行中的分頁共用一次請求** | 待確認 / 待審核 / 待點交 / 出借中 / 逾期 五個分頁都是同一批「進行中」資料的子集合,所以只向後端要一次,分頁在前端切 —— 點分頁**不再等後端**。只有「已歸還」與「全部」才會另外去拿歷史單。 |
| **⑤ 路由依參數決定讀多少** | `tables` 可以是函式:看 `filter` 是進行中還是歷史,決定要不要翻出已結案的舊單。 |

加上前後端兩層快取:

4. **CacheService**:每個「表 × 欄位組合」各快取 300 秒,任何寫入就 bump 版本號讓全部失效,不會讀到舊資料。
5. **前端 stale-while-revalidate**:切回看過的分頁先用快取立刻畫出來,同時背景重抓,內容有變才重畫;寫入動作會清掉前端快取。**15 秒內剛抓過的就直接用,連背景那一趟也省掉**。
6. **盤點頁批次化**:原本每個品項一次請求(N+1),改為 2 次請求取完。

實測(300 張借用單、其中 240 張已結案、60 項展品、96 位使用者,與「整張整欄都讀」相比):

| 頁面 | 少讀 |
|---|---|
| 展品目錄 / 展品管理 | −65% |
| 使用者 | −90% |
| 總覽 | −44% |
| 單台編號(盤點) | −29% |
| 借用單(進行中的分頁) | −50%,而且五個分頁只打一次 |
| 借用單(已歸還 / 全部) | 不變(本來就要翻歷史) |
| 我的借用 | −15% |

借用單列表的欄位本來就幾乎都要顯示,所以省的是「列」不是「欄」:進行中的分頁只讀未結案那一段。真正翻歷史的「已歸還 / 全部」沒辦法再省,要再快下去得把已結案的單搬到「歷史」工作表 —— 目前先不做。

另外,規則層在同一次請求內會把「每個品項的總數」與「品項 → 佔用中的借用明細」各建一次索引(放在 WeakMap,不碰資料本身),審核一整批時不用每張單都重掃整張表;資料一變就清掉。這一刀省的是 CPU,實測從 2.0 ms 降到 1.4 ms —— 不是瓶頸,但量大時不會惡化成平方。

> **正確性怎麼保證**:e2e 測試對每一個讀取動作都跑兩次,一次照上面的限縮讀、一次整張整欄讀,兩邊結果必須一模一樣;突變測試另外故意把欄位或列漏掉,測試必須因此失敗。

## 九、安全邊界摘要

- 所有請求只收白名單參數,限制長度 / 筆數 / 巢狀深度。
- 規則只在後端判斷;前端只負責顯示。
- 內部函式以 `_` 結尾,不會被當成 Web App 端點呼叫。
- 需要擁有者身分的維運動作以 `assertOwner_()` 擋住。
- 錯誤訊息一律通用化,不洩漏內部結構。
- 詳見 `SECURITY.md` 與 `docs/TEST-PLAN.md`(三層測試 + 突變測試)。

## 展覽檔期(v2.0,管理者)
一場展覽 = 一個專案,底下掛多張借用單(各廠區一張),各自走原本的核准 / 點交 / 歸還流程。

```
規劃中 draft ──確認檔期──▶ 已確認 confirmed ──結案──▶ 已結案 closed
     │                        │  │
     └────取消────▶ 已取消 ◀───┘  └──依地點產生借用單──▶ 借用單(已核准)
```

- **只有「已確認」會卡位**;規劃中 / 已結案 / 已取消都不佔庫存。
- 結案與取消之前,底下不能還有沒結束的借用單。
- 有缺口時不直接擋,但要管理者勾「知道有缺口,仍要確認」,缺口內容會寫進異動紀錄。

### 卡位怎麼算(避免同一批東西被扣兩次)
```
展覽佔用量 = max(0, 規劃量 − 已開單量)
已開單量   = 掛在這場展覽、狀態為「已核准 / 出借中」的借用單數量
```
| 底下借用單的狀態 | 展覽佔 | 借用單佔 | 合計 |
|---|---|---|---|
| 還沒開單 | 5 | 0 | 5 |
| 待審核 | 5 | 0 | 5 |
| 已核准 / 出借中 | 0 | 5 | 5 |
| 已駁回 / 已取消 | 5 | 0 | 5 |
| 已歸還 | 5 | 0 | 5 |

待審核的單還沒真的佔住庫存,所以展覽要繼續幫它佔著 —— 否則審核那段時間是空窗,別人剛好可以把東西借走。
已歸還之後展覽會把那一份重新佔回來,直到結案或改掉規劃量:這是刻意選保守的一邊(寧可擋住,不要超賣)。

### 改檔期
展覽改期**不會**自動改底下的借用單(會踩到已經出借中的單),展覽頁會列出日期對不上的單,
要一起延的用「批次延期」——逐張檢查延長那一段的庫存,一張失敗不影響其他張。

## 展後結算(v2.3)
展覽頁最下面的「展後結算」把規劃與實際攤開來對:

| 欄位 | 算法 |
|---|---|
| 規劃 | 展覽規劃清單的數量 |
| 實際借出 | 真的領出去過的(出借中 / 已歸還的單) |
| 已歸還 | 每一行的 `returned` 累加 |
| 短少 | 每一行的 `lost` 累加 |
| 未歸還 | 實際借出 − 已歸還 − 短少 |

- **駁回與取消的單完全不算**(東西根本沒出去);已開單但還沒領走的另外列成「已開單」。
- 同一個展品放在不同廠區會分開算(對照的 key 是「品項@地點」)。
- **系統不會自己去改庫存** —— 未歸還只是攤開給人看,追討是人的事。要沖掉短少請走正常的歸還流程(在歸還時填「短少」)。
- 展覽**結案的當下**會把結算結果存成快照。之後就算把借用單封存到歷史表,這裡的數字還在。

## 批次申請歸還(v2.3)
撤場時不用一張一張申請:展覽頁的「批次申請歸還」會列出底下所有出借中的單,預設全勾、整批全還、還回原本借出的廠區。
- 逐張獨立送出,失敗的單獨回報(跟批次核准 / 批次延期同一套做法)。
- **已經掛著其他請求(延期 / 轉借)的單會被跳過,不會被蓋掉。**
- 這一步只是送出申請,實際扣庫存仍然要管理者在「確認歸還」逐項核對 —— 那裡才是真的動庫存的地方。

## 借用單歷史(v2.3)
已結束的舊單可以搬到「借用單歷史」工作表,讓平常翻單快一點。操作與注意事項見 `docs/MANUAL-IT.md`。
讀取面的規則:
- **預設完全不讀歷史表**。只有「已歸還 / 全部 / 已駁回 / 已取消」這幾個分頁、而且使用者自己勾了「含歷史資料」才會讀。
- 掃單台條碼(`lookup`)會讀,因為單台的借用歷程不能在封存那天憑空斷掉。
- 刪展品(`deleteItem`)會讀,否則封存之後那個展品會突然變得可以刪,舊單就會顯示「(已刪除)」。
- 封存的都是已結束的單,本來就不佔庫存,所以**搬家不會改變任何可借量**。
