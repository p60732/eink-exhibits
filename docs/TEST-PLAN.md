## 使用者故事(核心)
- 身為**主管**,我要打開總覽就知道每項展品在庫幾個,以便不用派人去倉庫。
- 身為**同仁**,我要輸入展覽日期與品項立刻知道缺什麼,以便提早調度。
- 身為**展品管理者**,我要每台展品都知道在誰手上、何時該還,以便東西不會不見。

## 真實案例(流程層測試腳本)
同仁 A 送出 10/1–10/5 台北展的申請:看板 2 台、立架 6 個 → 管理者核准,系統自動綁定 E0001、E0003,
單子直接變「出借中」,A 與管理者各收到一封核准信 → 10/6 管理者登記歸還:E0001 正常、E0003 有損壞、
立架短少 1 → 已歸還;E0003 變「維修」、立架總數 10→9,兩方各收到一封結案信。

> v3.0(2026-10-01)之前這條流程中間還有「同仁簽收 → 當面輸入管理者工號+PIN → 同仁申請歸還 → 管理者確認」
> 四個步驟,已經全部拿掉。對同仁來說,只有第一步要填單。

## 邊界與例外
| 類別 | 案例 | 測試 |
|---|---|---|
| 日期 | 同一天重疊算衝突、隔天不算;跨月跨年;閏年;13 月 / 4/31 | rules.test.js |
| 逾期 | 逾期未還的展品在未來任何日期都算佔用 | rules.test.js |
| 數量 | 負數、0、超過在庫;待審核/已歸還不佔用 | rules + e2e |
| 例外 | 口頭借用(代為登記);部分歸還;遺失;盤點找回 | e2e |
| 權限 | 他人的借用單、同仁呼叫管理者動作、首次 PIN | e2e |
